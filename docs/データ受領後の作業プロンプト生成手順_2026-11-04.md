# 木戸表電子版｜データ受領後の作業プロンプト生成手順
更新日：2026年11月4日

この文書は、現行マスタープロンプトに追加する運用手順である。マスターの確定仕様を置き換えない。仕様の優先順位・表示項目・抽出規則は、常に最新マスタープロンプトを優先する。

## 1. 基本原則

データを受領するたびに、その時点で実行すべき作業を整理した「レース別・段階別の作業プロンプト」を生成し、可能な作業を直ちに実行する。①TARGET・②DATE 2・③東スポの3種類がそろうまで待たない。

作業プロンプトは実行指示書であり、マスターの仕様を再定義したり、独自仕様を追加したりするものではない。プロンプトを生成しただけで、抽出・反映・検証を実施済みと扱わない。

## 2. 受領時の処理順

1. 受領日時、ファイル名、形式、データ種別、対象レース、追加・差替え・再提出の別を記録する。
2. 日付・競馬場・レース番号・レース名を特定する。確認できない情報は推測しない。
3. 同一レースの過去の受領資料、抽出結果、作業状態と照合し、既存情報を保持する。
4. ①TARGET・②DATE 2・③東スポそれぞれを「未受領／受領済み／読取不能／照合要確認」で管理する。受領済みと抽出・検証済みを混同しない。
5. 今回だけで完了できる作業、他資料が必要な作業、先行可能な作業、判断保留が必要な作業を分ける。
6. 下記の固定構成で今回の作業プロンプトを生成する。
7. 生成したプロンプトに従って、可能な抽出・照合・反映・検証を直ちに実施する。
8. 結果・未確認事項・次に必要な作業をレース単位で保存し、次回受領時に引き継ぐ。

## 3. 作業プロンプトの固定構成

作業プロンプトには次を順番に含める。情報がない場合は「未確認」「未受領」「該当データなし」「読取不能」を使い分ける。

1. **作業目的**：今回達成する作業（①抽出、②抽出、③コメント整理、既存データへの追加、統合検証など）。
2. **対象レース**：日付、競馬場、レース番号、レース名、条件、頭数。確認済み情報のみ。
3. **今回受領した資料**：ファイル名、形式、種別、実際に読み取れた範囲。
4. **既受領資料・既存作業**：同一レースの過去資料、抽出済み・反映済み・検証済みの項目と成果物。
5. **馬番・馬名対応**：出走馬一覧と照合結果。不一致、重複、欠番、別レース混在の疑い。
6. **今回実施する作業**：抽出対象、保存先、反映先、処理順、照合方法。抽出項目はマスター第15項に従う。
7. **今回実施しない作業・保留事項**：資料待ち、根拠不足、ユーザー判断が必要な変更。
8. **厳守事項**：元データ保持、推測禁止、馬番・馬名照合、固定表記、マスター第15項、既存データ保護。
9. **完了条件**：抽出、照合、HTML反映、表示検証、本番反映を別々に定義する。
10. **作業後の報告形式**：受領状況、処理内容、未確認事項、検証結果、成果物の保存先、ローカル／本番の状態。

別のチャット・作業者に渡しても実行できるよう、対象レース・使用資料・作業範囲・完了条件を自己完結して記述する。「前述のとおり」「いつもの形式」だけで済ませない。マスター全体を毎回複製する必要はないが、必要な確定仕様と禁止事項を落とさず、根拠となるマスター項目を明記する。

## 4. 受領状況別の分岐

- **①TARGETのみ**：基本情報、騎手・調教師、血統、近3走など①由来項目を抽出・照合する。②・③由来の内容は補わない。
- **②DATE 2のみ**：②由来DATAを抽出・照合する。①・③由来項目は補わない。
- **③東スポのみ**：コメントを馬番・馬名に対応づけて原文保持し、記者名の削除対象を識別する。要約・言い換えをしない。
- **2種類受領**：受領済み2種類を抽出・照合・反映し、未受領資料に依存する項目は保留する。
- **3種類受領**：3種類を馬番・馬名で照合し、重複・不一致・欠落を確認して統合する。3種類が届いただけで完成扱いにしない。
- **再提出・差替え**：新旧資料の差分と影響範囲を確認する。採用元が明確でなければ黙って上書きしない。
- **複数レース混在**：レース単位に分割し、混在させない。特定できない断片は保留する。

## 5. 禁止事項

- 未受領データを受領済みとして扱わない。
- ファイル名だけで内容確認済みとしない。実際に読めた範囲を記録する。
- 過去資料を参照できるのにユーザーへ再提出を求めない。参照不能ならその事実を明示する。
- マスターにない項目・計算・変換・表示仕様を作業プロンプト内で新設しない。
- 「受領済み」「抽出済み」「照合済み」「反映済み」「検証済み」「本番反映済み」を混同しない。
- 作業プロンプト生成だけで止まらず、実行可能な作業を続ける。
- 本番反映の許可条件はマスター第10項に従う。プロンプトに本番反映と記載しただけでは書き込み許可にならない。

## 6. 完了報告

対象レース、受領資料、抽出・反映内容、未確認事項、検証内容、成果物、ローカル／本番状態を区別して報告する。未実施の作業を完了と表現しない。
