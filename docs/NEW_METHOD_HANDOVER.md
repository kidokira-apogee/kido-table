## 0. 最優先の運用宣言
- 今後の新規レース作成・更新は構造化JSON v1.0.0＋共通レンダラー方式を標準とする。
- 旧方式（レース画面全体をHTML文字列としてJSON等へ埋め込む方式）へ戻さない。旧形式は必要な場合の移行・差分照合の対象に限り、新規データの正本にしない。
- レースごとにHTMLを作り直さない。レース固有データをJSON化し、共通レンダラーへ渡す。
- 表示レイアウトは2026-11-01東京9R「紅葉ステークス」本番時点の固定レイアウトを全レースに適用する。構造・位置・余白・文字・色・段組・操作性を独断で変更しない。
- 本番main／公開サイトへ、明示的な許可なしに書き込まない。作業はfeatureブランチで行い、PRの検証と承認を経る。
- 会話の要約や古い試作品を仕様の根拠にしない。現行マスターとユーザーの最新指示を優先し、旧版で不足を補わない。

## 2. 確定した新方式
- JSON：schemaVersion = "1.0.0"
- 表示指定：render.layoutId = "tokyo9-production-locked"
- TARGET色情報：実データで保持を確認できた場合のみ render.preserveSourceColors = true
- 共通レンダラー：js/race-renderer.js
- スキーマ：schema/race-v1.schema.json
- 検証：tools/validate-race.mjs
- 一覧：data/races/index.json（軽量な一覧情報のみ）
- 詳細：data/races/<race-id>.json（選択したレースだけ読み込む）
- 馬番を主キー、馬名を照合キーとして扱う。頭数・馬番・馬名の一致を必須とする。
- TARGET：レース基本情報、馬プロフィール、近3走、血統等の担当範囲。
- DATE 2：馬単位の統計。第15-5項の掲載ホワイトリストにある項目だけをHTML用JSONへ格納する。原文は別途保持し、表示用データと混ぜない。
- 東スポ：今回コメント／前走コメントを別管理。明示区切りだけで分離し、記者名は表示本文から除去、原文は監査用に保持。イチオシは今回コメントだけ。
- DATAタブの順番は「詳細成績」「距離・コース」「条件別」「枠順・脚質」。
- 上部サマリーは5項目を固定順で表示する。
- 非掲載項目を、元データにあるという理由だけでJSON・画面へ追加しない。
- 不明・未確認を推測で埋めない。元データ未確認と、元データ上の該当なしを区別する。

2. GitHub PR #2とfeature/structured-race-renderer-v1の最新headを読み直す。ここに記載したSHAを現在値と決めつけない。
3. data/races/2026-11-01-tokyo-12.json、source-audit.json、tospo-comments.json、schema、validator、rendererを読み直す。
4. 上記4-A～4-Eを順に片付ける。仕様確認の繰り返しや新しい設計案の作成に時間を使わず、原本照合・監査記録修正・再検証を進める。
5. 変更ごとにCIを実行し、実際の結果を確認する。成功していない検証を成功と報告しない。
6. 進捗をこの文書とdocs/structured-renderer-progress.mdへ更新し、コミットSHA・CI run ID・未完了事項を残す。
7. PRのレビュー・マージ・公開は、ユーザーの明示許可を得てから行う。
