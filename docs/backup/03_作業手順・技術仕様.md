# 作業手順・技術仕様

## 標準フロー
1. Excel受領・最新版確認
2. シート・使用範囲・結合セル・見出し・値型・数式・色等を解析
3. ExcelとWebの項目対応表を作成
4. 掲載用データへ変換
5. 自動検証
6. 既存データ・保持対象を確認
7. 許可範囲でGitHub更新
8. Actions/Pagesデプロイ確認
9. 可能な範囲で本番画面確認
10. 実施・未実施・未確認を分けて報告

## 解析と変換
- ユーザーが指定した最新ファイルを正とする。
- セル位置だけでなく見出し・ブロック構造を使う。
- 馬番を基本キーとする。
- 空欄と0、文字列と数値を区別する。
- 小数点・符号・桁、近走順、コメント原文を保持する。
- 未定義項目を推測しない。
- Excel構造の想定外変更時は処理を止める。

## 公開前チェック
- レース情報・頭数一致
- 全馬の存在、馬番欠落・重複なし
- 馬番と馬名の一致
- 基本情報・近3走・血統・DATA・コメントの対応
- 数値・空欄・色・書式の一致
- 全馬・全項目のWeb表示
- PC・スマートフォン表示
- 既存レース・保持対象の非変更

重大な失敗があれば公開しない。

## レース画像の表示・追尾実装ルール（2026-11-18確定）

画像を掲載する場合は、docs/backup/01_最新確定ルール.mdの「レース画像の表示・追尾ルール」を必ず適用する。特に以下を確認する。

1. 初期表示が通常サイズであり、初期ロード時に追尾用縮小クラスが付かないこと。
2. 追尾ON/OFFボタンが画像の上部に見えること。初期状態はOFFで、ボタン表示も「追尾 OFF」。
3. スクロール開始前は通常表示を維持し、画像が画面上端に到達してから追尾すること。
4. OFFにすると追尾が解除され、通常フローへ戻ること。
5. 追尾中のフレーム幅は約65％を基準とし、画像は枠幅いっぱい・縦横比維持・高さ自動とすること。
6. 画像の縦横比を変えた場合もフレームの高さが画像に合わせて自動伸縮すること。
7. 画像タップで拡大表示できること。
8. Actions/Pagesの成功確認と、実機での初期表示・追尾ON・追尾OFF・拡大表示の確認を分けて報告すること。


## 画像データの一括受領・振り分け手順（2026-11-18確定）

### 受け渡し形式
- ユーザーは開催日ごとのフォルダを作成し、その中に各レースの画像をまとめて格納して一括アップロードする。
- 1レースにつき画像は1枚。
- フォルダ名：\`YYYY-MM-DD\`。
- 画像ファイル名：\`競馬場R番号_レース名.拡張子\`。例：\`京都11R_マイルCS.png\`。
- 例：\`画像掲載依頼/2026-11-22/京都11R_マイルCS.png\`。

### 振り分け処理
1. アップロードされた開催日フォルダを確認する。
2. 各画像のファイル名から競馬場・R番号・レース名を読み取る。
3. 既存のレース一覧・レースIDと照合する。
4. 一致した画像を対象レースの画像保存先へ配置し、レースデータに紐付ける。
5. 受領枚数と振り分け結果を照合する。
6. 判別不能・重複・レース情報不一致があれば該当分を保留し、ユーザーへ確認する。推測で配置しない。

### 完了報告
開催日、受領画像枚数、振り分け完了数、対象レース一覧、保留・不一致の有無を報告する。
